# Yumurta Admin — админ-панель площадки на iPhone

Приложение повторяет на телефоне всё, что умеет веб-админка `yumurta.ru/admin/`:
26 разделов в том же порядке, что и меню сайта, плюс вкладка «Заявки» — всё,
что сейчас ждёт администратора, и уведомления о новых заявках.

- Bundle ID: `ru.marketplace.admin`, имя на телефоне: **Yumurta Admin**, версия 1.0.0.
- iPhone, iOS 16+, SwiftUI, без внешних библиотек.
- Раздача — **только TestFlight** (внутренние тестировщики). В App Store приложение не публикуется.
- Сервер не меняется: приложение ходит в те же ручки `/api/admin/*`, что и веб-админка.

## Как устроено

| Вкладка | Что там |
|---|---|
| Сводка | Дашборд площадки |
| Заявки | Очереди «ждут действия»: заявки магазинов, публикация, лицензии, пополнения, возвраты, отзывы, жалобы, поддержка, жалобы на объявления, крон. Тап — открывает раздел |
| Магазины | Список организаций |
| Заказы | Заказы площадки |
| Ещё | Все 26 разделов + «Настройки приложения» (Face ID, уведомления, выход, версия) |

Вход — тем же e-mail и паролем, что на сайте. Если на сервере включена
двухфакторная защита, приложение попросит код из приложения-аутентификатора
(при первом входе — покажет ключ для привязки и кнопку «Открыть в аутентификаторе»).

Приложение по умолчанию закрывается Face ID (или код-паролем телефона) при
запуске и после 5 минут в фоне. Отключается в «Ещё → Настройки приложения».

Папки исходников:

- `Sources/App` — запуск, уведомления, палитра.
- `Sources/Core` — сеть (`API`), сессия и Face ID (`Session`), Keychain, форматирование, опрос очередей (`Notifier`), переходы (`Router`), серверный push (`AdminPush`), список разделов (`AdminSection`).
- `Sources/UI` — общие элементы экранов (списки с поиском и фильтрами, кнопки действий с подтверждением, поля форм, просмотр «Все поля» и т.д.).
- `Sources/Features/<Раздел>` — экраны разделов.

## Сборка

Проект собирается **XcodeGen** из `project.yml` (файла `.xcodeproj` в репозитории нет)
и **Codemagic** из `codemagic.yaml`:

- `ios-check` — сборка под симулятор без подписи: проверить, что код компилируется.
- `ios-testflight` — сборка, подпись и загрузка в App Store Connect; через 10–30 минут
  обработки сборка появляется у внутренних тестировщиков TestFlight.

Локально (на Mac): `brew install xcodegen && xcodegen generate`, затем открыть
`YumurtaAdmin.xcodeproj`.

Версия — в `project.yml`: `CFBundleShortVersionString` **и** `MARKETING_VERSION`
(поднимать оба). Номер сборки ставит Codemagic. Текст «Что тестировать» для
TestFlight — в `release-notes/ru.txt` (правьте перед каждой сборкой).

### Иконка

Временная иконка уже лежит в `Sources/Assets.xcassets/AppIcon.appiconset/icon_1024.png`
(щит с яйцом и галочкой, 1024×1024, без прозрачности). Чтобы заменить её своей —
положите PNG 1024×1024 без прозрачности под тем же именем.

## Что сделать владельцу в App Store Connect и Codemagic (один раз)

1. **Apple Developer → Identifiers**: создать App ID `ru.marketplace.admin`
   и включить у него возможность **Push Notifications**.
2. **App Store Connect → Приложения → «+» → Новое приложение**: платформа iOS,
   название «Yumurta Admin» (или другое свободное), основной язык — русский,
   Bundle ID `ru.marketplace.admin`, SKU — любой (например `yumurta-admin`).
   Карточку магазина (скриншоты, описание) заполнять **не нужно** — приложение
   не идёт в App Store.
3. **Профиль подписи**: в Apple Developer → Profiles создать профиль
   *App Store* для `ru.marketplace.admin` с сертификатом команды (тем же, что у
   продавца и клиента) и загрузить его в Codemagic
   (Team settings → Code signing identities → iOS provisioning profiles)
   под именем **`yumurta_admin_appstore`**. Сертификат `yumurta_dist` и
   интеграция `yumurta_asc` уже есть — общие с другими приложениями.
4. Залить папку `12 IOS-admin` в GitHub и
   подключить её в Codemagic как приложение (рабочие процессы возьмутся из
   `codemagic.yaml`). Запустить `ios-testflight`.
5. **App Store Connect → TestFlight → Внутреннее тестирование**: создать группу
   (или взять существующую), добавить в неё себя и других администраторов и
   добавить в группу загруженную сборку. Установить приложение TestFlight на
   телефон и принять приглашение.

Шаг «Карточка приложения и версия» в Codemagic сам проверит, что карточка с
bundle id `ru.marketplace.admin` существует, и остановит сборку с подсказкой, если нет.

## Уведомления

**Работает сейчас, без изменений на сервере — локальные уведомления.**
Приложение само проверяет очереди: при открытии, каждую минуту, пока оно на
экране, и в фоне (iOS запускает фоновую проверку сама, обычно раз в 15–60
минут, если приложением пользуются). Если очередь выросла — приходит
уведомление этой категории, на иконке — число всего ждущего. Категории
включаются и выключаются в «Ещё → Настройки приложения». Разрешение на
уведомления приложение спросит после первого входа.

Ограничение: в фоне iOS не гарантирует частоту проверок — если приложение
давно не открывали, уведомление может прийти с опозданием или только при
следующем открытии.

**Что нужно от сервера для мгновенных push (платформа `ios_admin`).**
Сегодня админам с сервера уходит только одно событие — «организация готова к
публикации» (`shop_publish_request`), и то лишь на устройства приложений
клиента/продавца: ручка `/api/v1/push/register` знает платформы
`web/android/ios/ios_seller`, а любое другое значение молча записывает как
`android`. Поэтому приложение админа свой токен пока **не отправляет**
(флаг `AdminPush.serverSupportsAdminPlatform = false`, код регистрации готов).
Заявка на сервер:

1. добавить `ios_admin` в список `$allowed` в `/api/v1/push/register` (`routes/api_v1.php`);
2. в `core/Push.php::toUser` — ветка `ios_admin`: отправка в APNs с
   `apns-topic: ru.marketplace.admin` (как сделано для `ios_seller`);
   значение enum `push_tokens.platform` сервер расширит сам (`Push::ensurePlatform`);
3. по желанию — больше событий для админов через `notifyAdmins()`: новая заявка
   магазина, обращение в поддержку, жалоба, возврат, пополнение к подтверждению.

После этого в приложении поменять `serverSupportsAdminPlatform` на `true`
(`Sources/Core/AdminPush.swift`) и выпустить новую сборку.

## Откуда берутся счётчики вкладки «Заявки»

| Категория | Запрос | Поле |
|---|---|---|
| Заявки на регистрацию | `GET /api/admin/dashboard?period=7` | `pending_regs` |
| Ждут публикации | `GET /api/admin/dashboard?period=7` | `pending_publish` |
| Лицензии на проверке | `GET /api/admin/documents?status=pending` | длина списка (сервер отдаёт до 200) |
| Пополнения продавцов | `GET /api/admin/wallets` | длина `pending` (запасной — `dashboard.pending_topups`) |
| Онлайн-оплаты без зачисления | `GET /api/admin/wallets` | `orphan_online` + `stuck_online` |
| Расхождения сверки | `GET /api/admin/wallets` | `reconcile.bad` |
| Пополнения клиентов > суток | `GET /api/admin/user-topups?status=pending` | элементы с `stale = true` |
| Возвраты | `GET /api/admin/returns?status=pending` | `total` (подпись — `dashboard.stale_returns`) |
| Отзывы | `GET /api/admin/dashboard?period=7` | `pending_reviews` |
| Жалобы | `GET /api/admin/dashboard?period=7` | `open_complaints` |
| Поддержка | `GET /api/admin/support/tickets?status=open` | `total` |
| Жалобы на объявления | `GET /api/admin/ads/reports` | `total` |
| Крон не работает | `GET /api/admin/dashboard?period=7` | `cron.stale` |

Тап по строке или уведомлению открывает раздел сразу на нужной вкладке:
«Ждут публикации» → «Заявки магазинов → Публикация», «Лицензии» → «Заявки
магазинов → Лицензии». Ссылка вида `yumurta-admin://section/registrations?tab=publish`
делает то же самое.
