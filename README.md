# Yumurta Admin — админ-панель площадки на iPhone

Приложение повторяет на телефоне всё, что умеет веб-админка `yumurta.ru/admin/`:
28 разделов в том же порядке, что и меню сайта, плюс вкладка «Заявки» — всё,
что сейчас ждёт администратора, и уведомления о новых заявках.

- Bundle ID: `ru.marketplace.admin`, имя на телефоне: **Yumurta Admin**, версия 1.0.0.
- iPhone, iOS 16+, SwiftUI, без внешних библиотек.
- Раздача — **только TestFlight** (внутренние тестировщики). В App Store приложение не публикуется.
- Сервер не меняется: приложение ходит в те же ручки `/api/admin/*`, что и веб-админка.

## Как устроено

| Вкладка | Что там |
|---|---|
| Сводка | Дашборд площадки |
| Заявки | Очереди «ждут действия»: заявки магазинов, публикация, лицензии, пополнения, возвраты, отзывы, жалобы, поддержка, сообщения продавцам, жалобы на объявления, крон. Тап — открывает раздел |
| Магазины | Список организаций |
| Заказы | Заказы площадки |
| Ещё | Все 28 разделов + «Настройки приложения» (Face ID, уведомления, выход, версия) |

Вход — тем же e-mail и паролем, что на сайте. Если на сервере включена
двухфакторная защита, приложение попросит код из приложения-аутентификатора
(при первом входе — покажет ключ для привязки и кнопку «Открыть в аутентификаторе»).

Приложение по умолчанию закрывается Face ID (или код-паролем телефона) при
запуске и после 5 минут в фоне. Отключается в «Ещё → Настройки приложения».

Папки исходников:

- `Sources/App` — запуск, уведомления, палитра.
- `Sources/Core` — сеть (`API`), сессия и Face ID (`Session`), Keychain, форматирование, опрос очередей (`Notifier`), переходы (`Router`), серверный push (`AdminPush`), список разделов (`AdminSection`).
- `Sources/UI` — общие элементы экранов (списки с поиском и фильтрами, кнопки действий с подтверждением, поля форм, просмотр «Все поля» и т.д.).
- `Sources/Features/<Раздел>` — экраны разделов.

## Сборка

Проект собирается **XcodeGen** из `project.yml` (файла `.xcodeproj` в репозитории нет)
и **Codemagic** из `codemagic.yaml`:

- `ios-check` — сборка под симулятор без подписи: проверить, что код компилируется.
- `ios-testflight` — сборка, подпись и загрузка в App Store Connect; через 10–30 минут
  обработки сборка появляется у внутренних тестировщиков TestFlight.

Локально (на Mac): `brew install xcodegen && xcodegen generate`, затем открыть
`YumurtaAdmin.xcodeproj`.

Версия — в `project.yml`: `CFBundleShortVersionString` **и** `MARKETING_VERSION`
(поднимать оба). Номер сборки ставит Codemagic. Текст «Что тестировать» для
TestFlight — в `release-notes/ru.txt` (правьте перед каждой сборкой).

### Иконка

Временная иконка уже лежит в `Sources/Assets.xcassets/AppIcon.appiconset/icon_1024.png`
(щит с яйцом и галочкой, 1024×1024, без прозрачности). Чтобы заменить её своей —
положите PNG 1024×1024 без прозрачности под тем же именем.

## Что сделать владельцу в App Store Connect и Codemagic (один раз)

1. **Apple Developer → Identifiers**: создать App ID `ru.marketplace.admin`
   и включить у него возможность **Push Notifications**.
2. **App Store Connect → Приложения → «+» → Новое приложение**: платформа iOS,
   название «Yumurta Admin» (или другое свободное), основной язык — русский,
   Bundle ID `ru.marketplace.admin`, SKU — любой (например `yumurta-admin`).
   Карточку магазина (скриншоты, описание) заполнять **не нужно** — приложение
   не идёт в App Store.
3. **Профиль подписи**: в Apple Developer → Profiles создать профиль
   *App Store* для `ru.marketplace.admin` с сертификатом команды (тем же, что у
   продавца и клиента) и загрузить его в Codemagic
   (Team settings → Code signing identities → iOS provisioning profiles)
   под именем **`yumurta_admin_appstore`**. Сертификат `yumurta_dist` и
   интеграция `yumurta_asc` уже есть — общие с другими приложениями.
4. Залить папку `12 IOS-admin` в GitHub и
   подключить её в Codemagic как приложение (рабочие процессы возьмутся из
   `codemagic.yaml`). Запустить `ios-testflight`.
5. **App Store Connect → TestFlight → Внутреннее тестирование**: создать группу
   (или взять существующую), добавить в неё себя и других администраторов и
   добавить в группу загруженную сборку. Установить приложение TestFlight на
   телефон и принять приглашение.

Шаг «Карточка приложения и версия» в Codemagic сам проверит, что карточка с
bundle id `ru.marketplace.admin` существует, и остановит сборку с подсказкой, если нет.

## Уведомления

**Push от сервера включены** (платформа `ios_admin`, APNs-топик `ru.marketplace.admin`,
сервер — волна А72, заявка П-29). После входа приложение отправляет токен в
`/api/v1/push/register` с `platform: "ios_admin"`. Сервер присылает push о новых
заявках магазинов и публикации, лицензиях, пополнениях по счёту, возвратах, жалобах,
обращениях в поддержку, жалобах на объявления, сообщениях организаций и отзывах на
модерации, а также о новых заявках курьеров, проблемах с доставкой и жалобах по вызовам
курьеров. Тап по push открывает нужный раздел (сообщение организации — сразу её чат,
заявка курьера — его карточку).
При выходе или истёкшей сессии токен гасится на сервере.

**Локальная проверка очередей осталась запасной.** Приложение само опрашивает
очереди — при открытии, каждую минуту, пока оно на экране, и в фоне (обычно раз в
15–60 минут, когда решит iOS): обновляет счётчики «Заявок» и число на значке. Пока
сервер подтвердил токен телефона, локальные баннеры о событиях, которые приходят
push'ем, не показываются (чтобы не было двух уведомлений); о том, чего сервер не
присылает (онлайн-оплаты, сверка кошельков, пополнения клиентов, крон), приложение
сообщает само. Категории включаются и выключаются в «Ещё → Настройки приложения»:
переключатель действует на баннеры при открытом приложении, локальные уведомления и
значок; push при закрытом приложении отключаются в настройках iOS.

## Сообщения продавцам

Раздел «Ещё → Сообщения продавцам» — переписка организаций с поддержкой площадки,
как `/admin/shop-support.php` на сайте (ручки `/api/admin/shop-support/*`). Одна
переписка на организацию: список с фильтрами (все / непрочитанные / открытые /
решённые) и поиском, чат с фото и PDF, «Отметить решённым» / «Открыть снова»,
звонок организации и владельцу. «Новое сообщение» — написать любой организации,
«Рассылка организациям» — одно сообщение многим (с подтверждением числа адресатов).
Из карточки магазина — кнопка «Написать организации». Непрочитанные переписки
видны во вкладке «Заявки».

## Курьеры

Раздел «Ещё → Курьеры» — «Курьеры Yumurta», как `/admin/couriers.php` на сайте
(ручки `/api/admin/pool/*`). Три вкладки:

- **Курьеры** — заявки и курьеры с фильтром статуса (новые заявки — первыми, с числом),
  поиск по имени, телефону и госномеру, сводка (на линии, вызовы, долг курьеров).
  Карточка: все поля заявки, фото лица и водительского удостоверения (сервер отдаёт их
  только с токеном администратора; на весь экран, щипок — увеличить), машина, кузов,
  грузоподъёмность, межгород и цена за км, деньги (долг, сальдо по заведениям, личный
  лимит наличных, поправка расчёта), последние доставки, жалобы, история решений
  (журнал). Действия: одобрить, отклонить с причиной, заблокировать / разблокировать —
  с подтверждением; причину курьер видит в приложении.
- **Проблемы** — проблемы с доставкой от заведений: «Оставить возмещение» / «Снять с курьера».
- **Жалобы** — жалобы по вызовам («пассажиры» — первыми): заблокировать курьера,
  предупредить, закрыть вызов, «Разобрано», «Не подтвердилась».

Push `pool_courier` (новая заявка) открывает карточку курьера, `pool_problem` и
`pool_complaint` — нужную вкладку. Вызовы и настройки раздела — пока только на сайте.

## Откуда берутся счётчики вкладки «Заявки»

| Категория | Запрос | Поле |
|---|---|---|
| Заявки на регистрацию | `GET /api/admin/dashboard?period=7` | `pending_regs` |
| Ждут публикации | `GET /api/admin/dashboard?period=7` | `pending_publish` |
| Лицензии на проверке | `GET /api/admin/inbox-counts` | `counts.documents` (старый сервер — длина `GET /api/admin/documents?status=pending`, до 200) |
| Пополнения продавцов | `GET /api/admin/wallets` | длина `pending` (запасной — `dashboard.pending_topups`) |
| Онлайн-оплаты без зачисления | `GET /api/admin/wallets` | `orphan_online` + `stuck_online` |
| Расхождения сверки | `GET /api/admin/wallets` | `reconcile.bad` |
| Пополнения клиентов > суток | `GET /api/admin/user-topups?status=pending` | элементы с `stale = true` |
| Возвраты | `GET /api/admin/inbox-counts` | `counts.returns` (старый сервер — `total` из `GET /api/admin/returns?status=pending`; подпись — `dashboard.stale_returns`) |
| Отзывы | `GET /api/admin/dashboard?period=7` | `pending_reviews` |
| Жалобы | `GET /api/admin/dashboard?period=7` | `open_complaints` |
| Поддержка | `GET /api/admin/inbox-counts` | `counts.support_tickets` (старый сервер — `total` из `GET /api/admin/support/tickets?status=open`) |
| Жалобы на объявления | `GET /api/admin/inbox-counts` | `counts.ad_reports` (старый сервер — `total` из `GET /api/admin/ads/reports`) |
| Сообщения продавцам | `GET /api/admin/shop-support/unread` | `threads` |
| Заявки курьеров | `GET /api/admin/pool/summary` | `pending` |
| Проблемы с доставкой курьеров | `GET /api/admin/pool/summary` | `open_problems` |
| Жалобы по доставкам курьеров | `GET /api/admin/pool/summary` | `open_complaints` |
| Крон не работает | `GET /api/admin/dashboard?period=7` | `cron.stale` |

Если `inbox-counts` не ответил (сервер до волны А72), четыре счётчика берутся
прежними запросами по спискам.

Тап по строке или уведомлению открывает раздел сразу на нужной вкладке:
«Ждут публикации» → «Заявки магазинов → Публикация», «Лицензии» → «Заявки
магазинов → Лицензии». Ссылка вида `yumurta-admin://section/registrations?tab=publish`
делает то же самое.

## Карточки по номеру и вход в кабинет (П-29, волна А72)

- Push или ссылка с номером открывает карточку сразу по id, даже если объекта нет
  на первой странице списка: заявки магазинов, возвраты, отзывы, объявления, города,
  журнал (`GET /api/admin/<раздел>/{id}`). На старом сервере — прежний поиск по списку.
  Карточки возврата, отзыва и объявления показывают подробности: слова покупателя,
  позиции, фото, историю, оценки по частям, ответы продавца, описание и контакты, жалобы.
- «Поддержка» — поиск по номеру, теме, автору, телефону и тексту переписки.
- «Журнал» — у правок магазина, промокода, категории, города, жалобы, страницы и
  модерации отзыва видно «Было» / «Стало» по каждому полю.
- «Страницы» — «Открыть на сайте» (`/page/{slug}`).
- Карточка магазина — «Войти в кабинет магазина»: одноразовая ссылка
  (`POST /api/admin/shops/{id}/enter-ticket`, живёт 60 с) сразу открывается в Safari,
  вход в браузере действует 4 часа.
- «Сводка» — оборвавшиеся онлайн-оплаты продавцов отдельной строкой
  (`pending_topups_online`); «Пополнения к подтверждению» — только ручные переводы.
